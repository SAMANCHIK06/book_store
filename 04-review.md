## Talablar qoplanishi

*   **Byudjet cheklovi noaniqligi:** "Byudjet yo'q" talabi faqat SMS xizmati uchun "tejamkor tariflar yoki bepul sinov imkoniyatlari" bilan qisman qoplangan. Biroq, to'liq "sayt" uchun hosting, domen nomi, SSL sertifikatlari va monitoring xizmatlari (Prometheus/Grafana, ELK stack) kabi muhim infratuzilma xarajatlari qanday qoplanishi aniq emas. Bu xarajatlar loyihaning ishga tushishi va barqarorligiga sezilarli ta'sir qiladi. (Xavf darajasi: Yuqori)
*   **"Sayt" funksionalligi to'liq emas:** "Sayt" talabi e-commerce loyihasi uchun asosiy funksiyalarni (mahsulotlar, savat, buyurtmalar, autentifikatsiya) qamrab olgan bo'lsa-da, mijozlar uchun muhim bo'lgan boshqa funksiyalar (masalan, to'lov gateway integratsiyasi, buyurtma holatini kuzatish, mahsulot qidiruvi, filtrlash, reytinglar/sharhlar) arxitekturada ham, build vazifalarida ham aniq ko'rsatilmagan. Bu "sayt"ning to'liq funksional bo'lishi uchun muhim bo'shliqdir. (Xavf darajasi: O'rta)
*   **SMS yuborish talabi qoplangan:** "SMS yuborish" funksiyasi arxitekturada ham, build vazifalarida ham Twilio/Vonage integratsiyasi va Celery orqali asinxron yuborish bilan to'liq qoplangan. Bu talab aniq va to'g'ri bajarilgan. (Xavf darajasi: Past)

## Reja va arxitektura mosligi

*   **Frontend holat boshqaruvi tanlovi yo'qligi:** Arxitekturada React uchun global holatni boshqarish uchun "React Context API yoki Redux/Zustand kabi holat boshqaruv kutubxonalari" ishlatilishi aytilgan, ammo build vazifalarida qaysi biri tanlangani yoki uning implementatsiyasi uchun aniq vazifalar mavjud emas. Bu frontend rivojlanishida nomuvofiqliklarga olib kelishi mumkin. (Xavf darajasi: O'rta)
*   **Deploy vazifalarining yo'qligi:** Arxitekturada "Deploy uchun talablar" bo'limida Docker konteynerizatsiyasi, CI/CD, Nginx, Gunicorn/uWSGI, monitoring va loglash kabi muhim deploy talablari batafsil ko'rsatilgan. Biroq, build vazifalarida bu talablarni amalga oshirish uchun hech qanday vazifa mavjud emas. Bu loyihani ishlab chiqarishga joylashtirishda katta bo'shliqni keltirib chiqaradi. (Xavf darajasi: Yuqori)
*   **SMS OTP endpointining aniqlanmaganligi:** Arxitekturada `POST /api/sms/send-otp/` endpointi "agar autentifikatsiyada ishlatilsa" deb ko'rsatilgan, ammo build vazifalarida bu endpointni implementatsiya qilish uchun aniq vazifa berilmagan. Agar OTP autentifikatsiya jarayonining bir qismi bo'lsa, bu muhim bo'shliqdir. (Xavf darajasi: Past)

## Xavfsizlik muammolari

Biroq, build vazifalarida bu funksionallikni implementatsiya qilish uchun hech qanday vazifa mavjud emas. Bu login va ro'yxatdan o'tish endpointlarini hujumlarga ochiq qoldiradi. (Xavf darajasi: Yuqori)
*   **Ma'lumotlar bazasi zaxira nusxalash avtomatizatsiyasi yo'qligi:** Arxitekturada "Ma'lumotlar bazasining muntazam zaxira nusxalari olinadi va xavfsiz joyda saqlanadi" deb belgilangan. Biroq, build vazifalarida bu muhim xavfsizlik chorasini amalga oshirish yoki avtomatlashtirish uchun hech qanday vazifa ko'rsatilmagan. Ma'lumotlar yo'qolishi loyiha uchun juda yuqori xavf tug'diradi. (Xavf darajasi: Yuqori)
*   **SMS telefon raqamlarini tekshirishning aniqlanmaganligi:** Arxitekturada "Raqamlarni tekshirish: SMS yuborishdan oldin telefon raqamlari formatini tekshirish va spamni oldini olish uchun cheklovlar qo'llash" zarurligi aytilgan. Build vazifalarida `sms_notifications` ilovasi uchun bu tekshiruvlarni amalga oshirish bo'yicha aniq vazifa yo'q. Bu noto'g'ri raqamlarga SMS yuborish xarajatlariga va tizimni suiiste'mol qilish imkoniyatiga olib kelishi mumkin. (Xavf darajasi: O'rta)

(Xavf darajasi: Yuqori)

(Xavf darajasi: O'rta)

## Release oldidan tekshirish ro'yxati

*   **Barcha API endpointlari uchun avtomatlashtirilgan integratsiya testlari mavjudligini tekshirish:** Har bir API endpointi (GET, POST, PUT, DELETE) uchun kutilgan javoblar va xato stsenariylarini qamrab oluvchi testlar mavjudligiga ishonch hosil qiling.
*   **E2E testlari to'liq qamrab olinganligini tekshirish:** Foydalanuvchining ro'yxatdan o'tish, tizimga kirish, mahsulotlarni ko'rish, savatga qo'shish, buyurtma berish va SMS tasdiqlashni olish kabi asosiy oqimlarini simulyatsiya qiluvchi E2E testlari yozilgan va muvaffaqiyatli o'tganligiga ishonch hosil qiling.
*   **Xavfsizlik tekshiruvlari o'tkazilganligini tasdiqlash:** Rate limiting implementatsiyasi, kiritish ma'lumotlarini to'liq tekshirish, SMS API kalitlarini muhit o'zgaruvchilari orqali xavfsiz boshqarish va telefon raqamlarini validatsiya qilish kabi xavfsizlik choralarining to'g'ri ishlashini tekshiring. SAST/DAST skanerlash natijalarini ko'rib chiqing.
*   **Deploy uchun infratuzilma tayyorligini tekshirish:** Docker konteynerlari, CI/CD quvurlari, Nginx/Gunicorn konfiguratsiyasi, PostgreSQL, Redis va Celery ishchilarining ishlab chiqarish muhitida to'g'ri sozlangani va ishlashini tasdiqlang.
*   **Monitoring va loglash tizimlari ishga tushirilganligini tekshirish:** Tizimning ishlashi (CPU, RAM, disk, tarmoq) va ilova loglari (xatolar, ogohlantirishlar) uchun monitoring va loglash tizimlari (masalan, Prometheus/Grafana, ELK stack) sozlangani va ma'lumotlarni to'g'ri yig'ayotganligiga ishonch hosil qiling.
*   **Ma'lumotlar bazasi zaxira nusxalash mexanizmi avtomatlashtirilganligini tekshirish:** Ma'lumotlar bazasining muntazam zaxira nusxalari avtomatik ravishda olinishi va xavfsiz joyda saqlanishini tasdiqlang.
*   **"Byudjet yo'q" cheklovi bo'yicha aniq reja mavjudligini tekshirish:** Hosting, domen va SMS xizmatlari uchun uzoq muddatli xarajatlar rejasi (masalan, bepul tierlardan keyingi tariflar, minimal xarajatli provayderlar) aniqlanganligiga va loyiha jamoasi tomonidan tushunilganligiga ishonch hosil qiling.
